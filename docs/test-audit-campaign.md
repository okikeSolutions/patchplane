## Browser/Worker import and build correction

This follow-up keeps Sentry unpatched and retains the existing bundle budgets.
The router's browser instrumentation uses `createClientOnlyFn`; the shared
server-function module loader uses `createServerOnlyFn` around its Effect
program. Vite import protection rejects the opposite runtime imports in dev
and production. Vitest's SSR host is exempt from those application import rules
because it also hosts browser instrumentation tests; the emitted-module gate
is still exercised by real fixture builds.

Production SSR minification is explicit. Alchemy already supplies the Worker
resolution conditions and `nodejs_compat`, so no browser Node polyfills or
package-internal aliases were added. The server-function manifest check now
parses syntax and accepts minified template literals while retaining the same
three required handler identities.

The primary owner for the added test claim is
`apps/client/build/runtime-boundaries.test.ts`. Its four tests build valid
small packages through Vite and prove that shared Sentry Core is allowed in
both runtimes, browser Sentry is rejected in Worker output, and Cloudflare
Sentry is rejected in browser output. A fourth adversarial build rejects an
external dynamic Node builtin import in the browser while allowing it in the
Worker. That adversarial test initially failed because Rolldown omits external
dynamic imports from chunk metadata. The gate now also checks dependencies
of emitted modules; the test passed after that correction. Each rejected case
has an allowed build
of the same fixture in the owning runtime. These tests protect the emitted
module gate, which source-import architecture checks cannot observe. No
production seams were added solely for testing. The former copied landing
route test was removed after audit: two of its three cases only searched
source/message strings for banned wording or link fragments. Locale-key parity
is retained as a parsed-message contract in `app-language.test.ts`. The
source-string claims were dropped because they did not exercise rendered links,
copy, or user behavior; the production build proves compilation only and is not
counted as link-behavior evidence. The header and status-badge tests also no
longer pin Tailwind class names or internal `data-slot` values. They retain

the separate theme test checks numeric contrast from actual light and dark
design tokens.

## Build warning resolution

standalone production build and the Alchemy Cloudflare build. The landing hero's
decorative Three/WebGL scene pulled 1.40 MiB of Three/R3F into the initial client
chunk. It is now a CSS ambient gradient with slow motion and respects the
existing reduced-motion rule. The diff viewer now uses Shiki's core factory,
JavaScript regex engine, and explicit lazy language loaders; unknown file

vendor groups capped at 400 kB. The emitted-module plugin now fails client
builds above Vite's unchanged 500 KiB warning boundary. Its adversarial Vite
fixture proves a generated oversized chunk fails the build. Package test lanes
also run sequentially to comply with the repository resource rule.
